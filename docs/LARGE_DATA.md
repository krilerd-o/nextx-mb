# ข้อมูลจำนวนมาก (หลักแสน–หลักล้านรายการ) บนแอป

## หลักการดึงข้อมูล
| เรื่อง | ทำอย่างไร | สถานะ |
|---|---|---|
| แบ่งหน้า | ดึงครั้งละ 30 รายการ เลื่อนใกล้ท้ายค่อยโหลดหน้าถัดไป (`page`/`limit`) ไม่ดึงทั้งตาราง | ใช้แล้ว |
| คอลัมน์เท่าที่ใช้ | ส่ง `cols=` เฉพาะฟิลด์ที่การ์ดแสดง (ชื่อ สถานะ ช่องบนการ์ด เจ้าของ เบอร์) แถวเล็กลง ~10–20 เท่า | แอปส่งแล้ว — เซิร์ฟเวอร์รองรับใน branch `feature/mobile-list-lite` (เซิร์ฟเวอร์เดิมจะคืนทุกคอลัมน์ ยังใช้ได้) |
| ไม่นับยอดซ้ำ | หน้า 2 เป็นต้นไปส่ง `with_total=0` ข้าม `COUNT(*)` ซึ่งเป็นส่วนที่ช้าที่สุดบนตารางใหญ่ | แอปส่งแล้ว — รองรับใน branch เดียวกัน |
| กรอง/ค้นหาที่เซิร์ฟเวอร์ | CRM ใช้ตัวกรองด่วน มุมมอง CV และ `q` ฝั่งเซิร์ฟเวอร์ ไม่กรองในเครื่องกับข้อมูลทั้งหมด | ใช้แล้ว |
| ตัดคำขอเก่า | พิมพ์ค้นหา/เปลี่ยนตัวกรองเร็วๆ ผลของคำขอเก่าที่มาช้าจะถูกทิ้ง | ใช้แล้ว |
| Cache | schema ฟิลด์เก็บ 5 นาที, หน้าแรกของแต่ละรายการแสดงจาก cache ทันทีแล้วโหลดใหม่เบื้องหลัง | ใช้แล้ว |
| รายการแบบ lazy | `ListView.builder` สร้างเฉพาะแถวบนจอ, รูปย่อขนาดก่อนแสดง | ใช้แล้ว |
| ตัวเลขสรุป | กราฟ 7 วันใช้ COUNT วันละครั้ง (`limit=1&with_total=1&cols=id`) ไม่ดึงรายการ | ใช้แล้ว |
| หน้ารายละเอียด | ดึงทั้งระเบียนเฉพาะตอนเปิด (`GET /api/entity/:m/:id`) | ใช้แล้ว |

## แนะนำฝั่งฐานข้อมูล / เซิร์ฟเวอร์ (เมื่อข้อมูลถึงหลักล้าน)
1. **Index** ที่คอลัมน์ที่ใช้เรียง/กรองบ่อย: `(business_id, deleted, modifiedtime DESC)`, `(business_id, createdtime)`, `(business_id, smownerid)`, คอลัมน์สถานะของแต่ละโมดูล, `activity(date_start)`, `activity(related_module, related_id)`
2. **ค้นหาข้อความ**: ใช้ `pg_trgm` GIN index กับคอลัมน์ชื่อ/เลขที่ เพื่อให้ `ILIKE '%คำ%'` ไม่สแกนทั้งตาราง
3. **Keyset pagination** (`after_id` / `after_modified`) แทน `OFFSET` เมื่อผู้ใช้เลื่อนลึกมาก (OFFSET หน้าหลักพันจะช้าลงเรื่อยๆ) — เพิ่มเป็น opt-in ได้แบบเดียวกับ `cols`
4. **COUNT แบบประมาณ** สำหรับ "ทั้งหมด" ที่ไม่มีตัวกรอง (`pg_class.reltuples`) หรือ cache ยอดรวมไว้ 1–5 นาที
5. เปิด **gzip** ที่ reverse proxy (JSON ย่อได้ ~80%)

## เมนูที่กรองในเครื่อง
เมล ไฟล์ แชท ร้านค้า งานภาคสนาม การลา กรองเฉพาะหน้าที่โหลดมาแล้ว (API ของเมนูเหล่านี้แบ่งหน้าฝั่งเซิร์ฟเวอร์อยู่แล้ว) — หมวด/คิว/ค้นหาเมล ยังส่งไปเซิร์ฟเวอร์
